Require both k/n >= p_min(k) and the predeclared one-sided lower confidence bound >= L_min(k); show k, n, interval and all stop reasons. ## Freeze the agent boundary, not just a feature count

Inventory the actual model-visible channel and action executor; names such as “diagnostic” do not make an intervention passive. Record full effective ON/OFF vectors, dependencies, system/tool/interface document hashes, source/build/ROM/vendor pins, save/start hashes, model artifact/quantization, serving context/cache/slots, sampling, executor, wall/turn budgets and stop paths. Freeze these within a comparison. Randomize balanced blocks and balance every executor across arms; allow no live policy/source changes.

| Privilege tier | Examples and ablation interpretation |
|---|---|
| Strategy support | Objective hints, coaching, battle recommendations, corrective supervisor messages and injected memories. Remove independently where executable switches exist. |
| Semantic execution | `navigate_to`, route solvers, automatic dialogue/battle advancement and other multi-step actions. These change the action space and timing, not merely prompt wording. RAM-aware semantic input refusals and automatic dialogue/menu/navigation corrections count as assistance whether or not text is delivered. |
| Structured privileged observation | RAM-derived coordinates, inventory, opponent facts, semantic UI readouts or world maps delivered to the model. Distinguish truthful facts from prescriptive hints; removing either does not remove post-run grading. |
| Minimal screen/buttons interface | Recorded visual frames plus declared primitive button actions. Still specify image resolution/cadence, button hold/release/frame duration, emulator speed/fast-forward/pacing, action batch limits, reset/retry policy, context/history/memory, model call cap, wall cap and allowed tool schema. This arm consistently ablates those semantic refusals and automatic corrections, retaining mechanical wire/schema/bounds checks. “Minimal” does not mean no harness or equal compute. |
| Measurement outside the agent channel | Passive replay, retained frames/RAM, native grading, provenance and post-run analysis. Keep equal across arms and prevent leakage into the agent. Never remove isolation, truthful grading, mechanical wire/schema/bounds validation of declared tool arguments, or evidence integrity. |

These tiers are an inventory, not a mandatory linear removal order. A group removal is a composite treatment; a smaller count can remove a more powerful privilege. If an independently controllable feature or safe primitive interface does not exist, name the implementation gap and stop short of pretending the ablation can run.

## Comparisons, add-back and cumulative minimal support

1. Use a contemporary frozen full-harness control against **one component removal**, or one predeclared dependency-consistent group removal. Publish the exact behavioral difference and activation checkpoint. A factorial interaction screen is an external cohort under repository rules; it does not identify every component from a bundle contrast.
2. Predeclare targeted interaction contrasts where features substitute for or depend on each other. Test removal plus add-back from a fresh identical start; a restored outcome is mechanism evidence, not proof of universal necessity. Schedule any diagnostic rescue as its own arm/window with declared trigger and restored support. Never manually rescue, replace or erase the original failed trial; a rescued run cannot count as unassisted success.
3. Freeze a final cumulative candidate containing every accepted removal and compare it against full harness on fresh held-out trials. Individual noninferiority does not imply joint noninferiority. Confirm the cumulative stack, dependencies, downstream milestones and failure modes before calling it minimal support.
4. Call a stack **minimal among the tested configurations at this checkpoint/budget**, not globally minimal. Preserve alternative nondominated stacks and disclose untested combinations. Retain failed removals and add-back receipts.

## Decide success and sample size before sampling

For each confirmatory family, declare one primary binary outcome: post-start earned target within the common cap. Predeclare a completion noninferiority margin delta, confidence/test method, alpha, power, multiplicity family and secondary efficiency/regression limits. A typical risk-difference rule is lower confidence bound for (p_removed - p_full) > -delta; absence of a significant superiority difference is **not** noninferiority. Freeze exact boundary conventions and a validated interval/test implementation before launch.

Size fixed N from the baseline rate, smallest tolerable loss/effect, desired power and operator GPU-hour budget. The repository `power.py` supports its documented superiority/Fisher plans and multiplicity inputs; do not claim that negating a lift sizes a valid noninferiority trial. A suitable validated noninferiority power calculation is a future prerequisite. Repository eight-per-arm screens nominate candidates only; they do not establish equivalence, minimality or sufficient precision. Declare comparisons across components, checkpoints and model generations (for example a Holm family or a justified hierarchical procedure), and use fresh held-out confirmation after selection. If budget cannot answer the chosen margin, report the detectable effect/precision or leave the result inconclusive.

Use one analysis at fixed N; no optional stopping, favorable reruns or mid-cohort policy changes. Predeclare every termination path and failure category. Under the prospective repository design contract, stuck/stalled/budget/model_error/crash are not-reached outcomes in their arm; only verified outside-arm outages may be replaced under the declared rule, with originals retained and imbalance/sensitivity reported. Operator interruptions or unsupported observation/grading must remain explicit; specify how they affect the primary estimand and sensitivity bounds before launch. Do not import the historical descriptive census's U handling as a replacement for this prospective trial contract. Time-to-target observations are right-censored when unresolved, not zero or fast successes; rank failures after successes and never base a benefit claim solely on survivor medians.

## Report a support frontier across generations

At each checkpoint, show conditional continuation reliability and intervals, end-to-end common-start reliability, acquisition cost, LLM turns/time/tokens, primitive button-action and held-frame counts, game frames, observation cadence, frontier, failure/loop/recovery classes, recurrence and delivered assistance exposure. Removing semantic tools changes action granularity: fewer LLM turns across different interfaces is not itself greater efficiency. Hold wall/token budgets and the frame/action contract fixed and report their realized consumption alongside decision turns. Retain the cross-model skill's explicit proxy labels and unavailable measurements. Plot support-versus-performance Pareto fronts using declared privilege vectors and independent cost axes, not a single intelligence/support index. A stack dominates another only under the declared reliability and cost criteria; retain uncertainty rather than force a winner.

For each later model generation, repeat a **fixed anchor** interface/start/task/budget comparison and a separate **contemporary full-harness** comparison. Preserve hardware/runtime/tokenizer differences and tool compatibility; remeasure anchors when compatible rather than silently replacing history. A generation-specific support ledger records which guidance was removed, where noninferiority was confirmed, add-back/rescue evidence, minimal tested stack, failures, source pins and confidence. Decreasing dependence is supported only at the tested frontier and budgets; equal checkpoint performance does not prove full-game or general intelligence. No automatic promotion follows.
