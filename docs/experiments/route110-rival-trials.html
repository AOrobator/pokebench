6. Order, executors and failures

Both arms run in randomized balanced blocks on one Qwen3.8 server that holds both GPUs, so each wall hour is 2 GPU-hours; the table above is doubled from power.py for that reason. Qwen3.6 runs after, one instance per GPU, each GPU running both arms. Stop anything only after checking no live run uses that server. e09e holds both GPUs until about 10:35 PM on Nov 7, unless the operator stops it.

Every trial runs the full 20 minutes: the control base has no stop target, so a win carries on toward Mauville and a win is read from the milestone. Costs exclude a few minutes of start-up per trial. aeb8's quickest return after a loss was 19 minutes, so one fight per trial is close to guaranteed for Qwen3.8. Only trials with no run_start are re-run.

7. What could fool us, and what this cannot tell us

ThreatControl in this design
One save, one partySame save for all arms; the same replay can make a 7442 save (Marshtomp 20, Taillow 13) for a second start.
Same RNG every trialDifferent button timing changes the RNG. Check the fights are not identical before reading results.
The win is mostly luckaeb8's win needed a critical hit, which is why the lift must be large to show at this N.
Guide row on loadChecked: in rehearsal the right line was the last message of each arm's requests.

This cannot say whether either line helps a run from boot, or whether level 26 by grinding is the better plan overall. That needs a boot test.
