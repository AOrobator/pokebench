Briefing exit facts

The supervisor briefings told the model that exits it had just used were untried, and they put the one exit that mattered last, under a bare map number. With this switch on, used exits and triggers the player walked over leave the untried lists, the stall briefing leads with the exits to maps not yet entered and the dialogue of the latest story step, and warp destinations carry the name the readout itself gave them. Off: every briefing is byte-identical to today.

Why: cook #2 (bundle arm, run 2026-10-16T02-23-17_qwen36-gpu1_sh02)

Which exit a map change used

A warp can lead to its own map (the teleporter pads in pokeemerald AquaHideout_B1F, the Trick House puzzles). Two states on the same map more than two tiles apart (a ledge hop is two) with a warp to this map next to the start count as using that warp and the one next to the arrival.

Warp destinations are read from the game's own warp events (env/pokebench_env/world.py read_targets: group, number and destination warp id). A door arrival captured one step out of the door (a door exit walks the player down a tile) still finds the door within one tile.

Step triggers: one now counts as tried when the recorded states show the player walking onto it at any step of a batch, not only where the batch ends. Arriving on a trigger through a warp, or standing on one, still does not count (the 2026-10-15 finals rule: a coordinate event runs when the player steps onto its tile, not on a warp arrival). Tried lists still start over when the readout's Story line changes; the exits of the call that changed it stay tried.

Names come from the readout itself

The briefing collects the names the model's own readouts gave to maps: the Location line for the map it describes, and destinations written -> NAME (map g/n) or Warp to NAME (map g/n) (named-warp-destinations-v1, world-destinations-v1). A map no readout named keeps its bare id. So in a control arm without named warps, the briefing does not show a destination name the model's readout never showed. Room headers are not this switch's: since claude/displayed-names-everywhere landed, roomOf shows the state's location_display (the Location line's name), so in new runs both read the same. The sh02 excerpts below predate that, so their headers still show source names.
