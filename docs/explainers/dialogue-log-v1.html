Dialogue log and recall_dialogue

The harness writes down every dialogue page the model was actually shown, in order, for the whole run. The model can search it with the recall_dialogue tool when it forgets what someone said or wants to check where it heard something. Off by default.

Why

Recent runs lose instructions to context pruning. By the time a run has been wandering Littleroot for 300 turns, Mom's line about the neighbors is long gone from the model's context. Navigation evidence memory pins the newest few pages (at most 5, each clipped). This log keeps all of them and lets the model ask.

What gets recorded

FieldMeaning
#seqEvent number of the delivered state. It can be checked in the run log and replay.
turnModel turn when the page was delivered.
roomLocation line from the readout, or "unknown room". With bounded navigation on, the map id the readout already shows is added, for example "(map 1/0)". Identity always uses location plus map id, so two maps with the same label never merge.
at x,yPlayer tile, only with live-player-position-v1.
facing NAME at x,yThe named object on the tile the player faces, only with named interactions and position on. It is who the player was facing, which is usually but not always the speaker (a TV or a cutscene can talk too).
textThe active field-message buffer, quoted. It can include pages not yet shown on screen.

The tool

Arguments are all optional: contains (words, up to 80 characters, case-insensitive), room (location text, up to 80 characters) and last (1 to 20, default 8). Each page is clipped to 650 characters and the whole reply stays under 6,000. The reply always says how many pages matched, how many were shown and how many were left out.

Illustrative reply shape (not from a recorded run yet):

DIALOGUE LOG: quoted game text you were shown, newest first. Past text; the current screen overrides it. 2 of 41 entries match.
#3120 turn 286 · LITTLEROOT TOWN BRENDANS HOUSE 1F · at 8,4 · facing MOM at 8,5: "…"
#2901 turn 275 · LITTLEROOT TOWN BRENDANS HOUSE 1F · at 8,4 · facing MOM at 8,5: "…"
2 shown.

Every call and reply is an ordinary tool_call / tool_result pair in the run log, so it shows up in the timeline, Activity History and replay like any other tool. Harness Config documents the tool's inputs and outputs.
