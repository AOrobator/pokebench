Conversation ledger

Every observe, press and navigate_to result on the free overworld gets one block right under the readout's Story line. It quotes the latest conversation in which the game prints a speaker's name, whole, with its speakers and turn ("MAY, turn 450"). Then it lists every room visited, newest first, with the last line heard in each. The harness picks nothing by meaning. The game's own NAME: prefix decides which conversation counts. There is no model tool, no prompt line and no model-written text.

Why a v2

The PokeBench review of 2026-10-17 (harness engineer, evaluation integrity, data scientist, ML engineer) found four problems with instruction-ledger-v1. The operator then decided to drop dialogue-log-v1 and note_contradiction and build this switch instead. v1 itself is unchanged; it is a separate switch.

Which conversation is pinned

  • A conversation is every field page of one auto-advance call, in order. Battle text (pages with a battle turn) never counts.
  • Pages in a named conversation that carry no prefix themselves keep the speaker auto-advance carried within the conversation. For example, MOM's "He lives right next door" (PlayersHouse_1F_Text_GoIntroduceYourselfNextDoor) follows "MOM: Oh… It's over."
  • A page counts once its tool result reached the model. The result that delivers a conversation already pins it. An error result delivers nothing.
  • Before any named conversation, the latest field page stands in, labelled "the latest field page".
  • No character list, milestone order, map knowledge or route knowledge is used (PB4). This differs from story-destinations-v1, which uses character presence's story-character table.

Where "last heard" comes from

Rooms are keyed by the game's location and map id. They are named the way the readout names them once a readout has shown the room (for example "RRED's HOUSE 1F (map 1/0)"); a room known only from a page uses the page's map name. Map ids appear when bounded-navigation-v1 is on, as in the readout. The list is ordered by the latest turn the player was there, newest first. Nothing is clipped and there is no cap: the context window is the only bound.

  • The speaker label is the game's NAME: prefix, with the prefix moved out of the quote. A faced sprite reads "MANIAC (sprite kind, not a name)", a faced object reads "Wall clock (faced object)" and an unlabelled page has no label.
  • Line breaks in the game's text are printed as spaces. Every other character is kept.

  • Record: the block is part of the recorded tool_result text, so forensics and replay see exactly what the model saw. There is no ledger_context event, because the decision probe replays ledger_context as a trailing user message and v2 is not one.
