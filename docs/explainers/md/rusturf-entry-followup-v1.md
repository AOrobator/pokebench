## Executive summary

**One reminder follows the first safe, current Rusturf observation actually delivered to the model.** It prioritizes local inquiry and following through on game replies. Implementation checks are ongoing; this automatic policy has no measured gameplay benefit yet.

## When the reminder appears

| Condition | Result |
|---|---|
| Switch OFF | Previous behavior; no added context. |
| Rusturf map \[24,4\], matching name and current coordinates | Eligible only with coherent, free overworld control. |
| Battle, menu, dialogue, diagnostic or missing/unknown state | Wait for a safe observation. Leaving cancels this candidate. |
| Native grunt-defeat and Goods-recovery evidence | Both must be known false. Either complete or unknown suppresses. |
| Successful tool result | Same run, state sequence, call ID, tool name and exact text; present before and after existing context processing. |

Starting inside counts. Historical restored observations do not trigger; a fresh current observation can.

## One decision, then ordinary history

\1. Current delivered observation → eligibility checks

↓ eligible

\2. Existing memory and checklist → reminder as the last user message

↓ model chooses

\3. Failed/aborted response → pending retry<br>
Successful exposed response → consumed for this run, including re-entry

The note uses dynamic location/position, generic local priority, inquiry, conditional tool binding, task continuity and observed-resolution retirement guidance. It supplies no prior-run quotes, actor IDs, Peeko facts or hideout route. Completion guards add no unseen story facts.

No automatic action, context reset or goal selection occurs. Dialogue from this run remains ordinary history/existing memory; this hook adds no extractor. The note is added per request and is not persisted in the model’s conversation history. Repeat context processing removes only this hook’s own stale transient notes.
