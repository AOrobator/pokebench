Milestone stall stop

A run that has stopped making progress ends early. With this switch on, a run ends as stalled after 10 minutes of play with no new milestone. The wall budget (45 minutes in the winner-gate finals) stays the hard cap.

How the clock works

Rules, as coded

RuleValue
WindowSTALL_STOP_MS = 10 × 60,000 ms
Clock startsAt run start, on the same run clock as the wall budget
Restarts onA milestone event whose origin is not present_at_start
PausesExcluded, the same accounting as the wall budget (BudgetTimer)
End reasonstalled, a new run_end reason; the run is recorded in full, like a budget end
Model inputUnchanged: the model is never told about the timer
OffNo timer. Runs end exactly as before.

Why it exists

Operator, 2026-10-15: end a full run after 10 minutes with no new milestone, keeping 45 minutes as the hard cap. The winner gate's finals run from boot with it on, so stuck finalists stop early instead of burning the full budget. It is a general switch that any preset can use.

It is a budget rule, not a treatment: its pending experiment entry is marked blocked so it never joins the queue.
