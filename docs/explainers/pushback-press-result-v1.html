Push-back press results

Scripts move the player while dialogue auto-advance pages their message, between two snapshots of one press, and between one call and the next. The results only described the model's own input, so a push-back read as "no net movement", "turned left -> right" or only as a restarted conversation, and navigate_to said to call it again. With this switch on, press and navigate_to results say that a script moved the player, with the tiles. Off: today's text.

"Took over" needs free controls when the press began, the same tile, a message or running script holding the controls after it, and the player facing away from the direction pressed. The walk-batch split counts the tiles the player actually moved (at least the first input) as sent.

Wiring

FeatureSet["pushback-press-result-v1"] → toolSwitches().pushback → withDialogueAutoAdvance, which applies pushbackPressResult (press-result.ts) to the press result when auto-advance ran. decision-probe keeps auto-advanced results as recorded and refuses to flip this switch on them, as for the other switches that shape that text.
