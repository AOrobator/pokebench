## Contracts

`GameState.position` uses active player `gObjectEvents` currentCoords (+0x10, two signed 16-bit cells), minus MAP_OFFSET=7, instead of the last save position. The player slot comes from verified `gPlayerAvatar+5`; facing is the same object's low nibble at +0x18. Invalid/inactive/non-player identity is unavailable rather than a zero position. The parent field-initialization guard must be preserved when integrating this delta.

The local ASCII grid keeps its existing bounded window but labels every X column and Y row in the same map coordinates as player/targets. North decreases Y; east increases X. Out-of-map cells remain unknown. Local live object/warp descriptions remain intact.

Optional `interaction_targets` is added to JSON/event schemas; historical logs without it still validate. Null means inventory unavailable, not an empty map. The readout enumerates all current-map warp, coordinate-trigger and background events, live visible script-bearing objects, and the entire live mutable map's metatiles whose source behavior predicates return interaction scripts. Live object positions are never taken from templates. Null-script decoration objects remain visible in the grid but are withheld as interaction targets. All targets are conditional: flags, elevation, scripted ownership, game-specific overrides and current control lock may gate them. Activation distinguishes A from step, background facing restrictions are explicit, and warp destination map/warp IDs preserve the dynamic 127/127 sentinel.

Background labels deliberately remain generic event types rather than guessed object names. A target at (5,1) in Brendan's bedroom is the clock, verified by an actual interaction below. Arbitrary decorative behaviors are not assigned interactions. Field-move interactions requiring party/flags (Surf, Dive, Cut, Strength, Rock Smash), mutable RAM-script overrides and per-candidate flag evaluation are not claimed complete by this inventory.

`press` captures an optional verified state before dispatch, then compares it to the validated state in the final observation/frame. Net movement, turning without movement, map/screen transition, observed field lock, and unavailable readiness are distinct. An unchanged directional endpoint is **blocked or unavailable**, because snapshots cannot prove every frame accepted input or exclude a temporary lock. A batch reports only net changes; intermediate movements or interactions are not reconstructed. No pathing, navigation solver, objective state, objective tools or prompt changes are added. Run feature metadata declares the extra observation fields and feedback.
