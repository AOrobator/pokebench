- OFF: today's text byte-for-byte. Independent of `battle-text-auto-advance-v1`.

- Design decisions (as built):
  - **Where the text goes.** battle-details-v2 ON: the `Battle details:` line's input clause (`_input_text`) changes. battle-details-v2 OFF (the bundle's control arm, which also has expanded battle information off): a separate `Battle input: <clause>` line right after `Battle details: unprovided` / `Battle state: ...`, only when there is a message or YES/NO clause. So the switch works ON in both arms with no `needs`.
  - **Clauses** (only replace OFF's `resolving (no input until the game asks)`; ready inputs and replay unchanged; finishing appends ` · <clause>`): waiting → `battle message waiting: "<page>" — press A or B to continue`; printing → `battle message printing: "<page>" — still being written; no input needed yet`; battle-script YES/NO box ready (Cmd_yesnobox and friends, B answers NO) → `battle YES/NO box open (...), cursor on YES|NO — UP or DOWN moves the cursor, A answers the highlighted choice, B answers NO`; reader diagnostic → `battle message unreadable (...)`; printer idle while the battle runs (`text_phase` busy) → `resolving (the game is playing animations or a message that closes on its own; no input until the game asks)`. `text_phase` screen (another screen owns the callback) keeps OFF's text.
  - **"Closing on its own" is not read from the script.** Raw RAM 7790–7816 of the showcase run shows auto messages stay on screen through `waitanimation` etc., not only `waitmessage`, and an idle printer cannot tell a shown message from a healthbox name in the buffer. So the idle clause says the true general fact and quotes no text.
  - **Page** = text written since the window was last cleared (`\p`, CHAR_PROMPT_CLEAR) up to the next wait (`\p`, `\l`, FC 09) at or after the printer's cursor, line breaks as spaces, whole. New `BattleMessage.page` (optional in the TS schema so older recorded states stay valid).
