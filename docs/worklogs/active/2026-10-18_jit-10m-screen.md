### Outcomes and graphs
User-selected fixed-time progress replaces the template skill's usual target-milestone binary primary. Primary: the run's furthest validated required story milestone within ten minutes; ties break by earlier first arrival at that same milestone. Use the canonical required-story ordering, not the count of optional trainers, catches or house visits. Show the complete distribution and the descriptive pairwise probability of superiority; this screen neither promotes an incumbent nor establishes a confirmatory result.

1. **Progress:** cumulative native milestone arrival-time lines, individual runs and cohort spread, completion k/12 at each checkpoint, and each run's furthest frontier at ten minutes. Include all early required checkpoints the native grader exposes. Missing, censored and unrecorded events are distinct; no zero substitution. Preserve human, prior incumbent and best actual agent-run anchors where comparable, otherwise label timing/start mismatch or unavailable. Do not splice a best-of-each-milestone envelope into a purported single run.
2. **Input tokens and cache:** per-request logical prompt tokens, uncached input and cache reads, plus per-run totals; verify the pinned provider adapter's accounting before adding input to cache_read. Do not treat estimated context size as server usage. Actual processed prefill tokens require server telemetry; mark unavailable if absent.
3. **TTFT:** per-request empirical distribution, median/tail, per-run summaries and screen-state split. Include thinking/tool deltas according to a documented first-stream-event definition; missing TTFT is unknown, not zero.
4. **Thinking and output:** total generated output tokens and, only if the server reports them separately, reasoning tokens. Do not estimate reasoning tokens from string length or rename all output tokens as reasoning. First thinking to last thinking duration may be a separately labelled wall-time proxy, with streaming limitations disclosed.
5. **Total inference latency:** request-to-completion distributions and per-run total inference seconds. Show separately from end-to-end gameplay elapsed time and tool execution time. Failures and incomplete deadline-cancelled requests remain visible.
6. **Correct actions:** requires a preregistered, screen-specific trace-scoring rubric and arm-blinded annotations. Mechanical validity, movement, and state changes do not establish a correct strategic action. Show correct/incorrect/unscorable counts by screen, with annotation coverage. If reliable scoring is unavailable, label this chart unavailable rather than invent a success detector.
7. **Invalid tools:** separately count unavailable-tool selection, malformed/invalid arguments, execution errors and model errors, with both counts and rates per attempted call. A legitimate blocked movement is not automatically a malformed tool call.
8. **Useful decisions per second:** only scored-correct decisions divided by elapsed seconds in the scored windows, with inference-only throughput separately labelled. Show scoring coverage; a valid-call rate or a state-changing-action rate must not be called useful decisions. Native milestone progress per minute remains the objective gameplay efficiency evidence.

Run-level results are the experimental units. Per-turn distributions are descriptive; thousands of correlated turns do not create thousands of independent trials. Break out screen composition so one arm reaching battles sooner cannot masquerade as an inference improvement. Preserve request, turn, run, screen, executor, stop reason and timestamp linkage. Additional thread suggestions (interventions, repeated mistakes, recovery and retrieval failures, inference cost) require defined labels or actual telemetry; expose unavailable fields rather than infer them from narrative.
