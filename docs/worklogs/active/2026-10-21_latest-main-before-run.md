# Latest main before each automated exploratory run

User authorization: next automated bundle runs must pick up latest main before each run, without interrupting current runs. Current whole-map loop updates once per four-trial round; its active last pair stays on its existing frozen build.

Scope: opt-in latest-main mode for fixed-run dry-run only, loop launch wiring, fresh per-trial commit and feature configuration, immutable per-trial preset/definition and ledger provenance. Approved fixed experiments retain their existing whole-cohort pin. Existing lane, plan, start, budget and serving contract changes hold new launches rather than silently changing the running round. Build and launch must use the same captured commit; main advancing during preparation causes a hold/recheck. Never mutate a running trial checkout. Replace only the detached loop supervisor after review/landing, leaving the existing fixed runner and gameplay processes alive; its replacement waits for the existing leases.

Proof: fake-host rehearsal changes main/feature bits between trials and while another lane is running, verifies per-run commits/presets and adoption; default fixed-pin invariance, prepared-build race, stale-main refusal, failure paths and stop behavior. Full gates and independent cloud review before landing. Viewer refreshed before any newer-build trial. No new gameplay launch during implementation; user has authorized continuation by the existing automated loop.

Design correction before review: a long-lived runner cannot validate future new switches with its old registry. Use a fresh launcher process from the captured main commit for each single-lane trial instead; code, registry and bundle definition all update together. Preserve the existing fixed runner as the execution/lease/recording owner. New dry-run arm/lane selection is exploratory only. The controller prepares immutable commit-specific launcher clones, then invokes the existing fixed runner for one trial, with fresh main resolution before every invocation.

## Implementation and proof

The controller resolves refs/heads/main for every single-lane trial, prepares a clean commit-specific launcher clone (fresh registry/config), builds the immutable trial checkout through productionFixedHost, rehearses both arms on every lane through the actual CLI with a scratch runs root and fake executor, refreshes/verifies the viewer, and rechecks main before invoking just fixed-run dry-run with explicit --arm/--lane. The existing FixedRunner remains the sole gameplay/lease/recording owner and approved fixed experiments are unchanged. Each exploratory trial has its own lane/arm ledger and exact commit in the normal run_start. Future arms alternate per lane; this is ongoing exploratory development, not a fixed-build confirmatory comparison.

STOP/ABORT is global to future starts; active trial processes are never signalled. Existing runner status, model-pool leases, busy ports, pause/stop and frame-cap holds prevent new starts. Previous ledgers and failed trials are retained. A clean captured main with unsupported single-trial CLI fails the scratch rehearsal, never falls back to paired launching. Main moving during preparation holds/retries. New controller identity and per-lane commit/runner receipts are in runs/dryruns/latest-main-*.
