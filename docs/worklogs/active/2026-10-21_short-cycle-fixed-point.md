# short-cycle-fixed-point-v1: 2-4 turn cycles of the same calls and states count as a fixed point

(First built as `ping-pong-fixed-point-v1`; renamed before landing when the coordinator widened the scope to short cycles. Branch `claude/ping-pong-fixed-point` keeps its name.)

## Problem Statement

duplicate-turn-collapse-v1 (on in both arms) leaves out of each request a run of 3 or more identical turns: the same thinking, text and tool calls, each leaving the same `planState`. Two bundle runs looped without ever producing such a run (both read-only):

- `runs/2026-10-20T19-58-04_qwen36-gpu0_ef9f`, from turn 131 (8:06 PM New York): `press {buttons:["RIGHT","A"]}` every turn. Each result alternated between the clock confirmation (`clock_confirmation`, NO highlighted) and the clock adjustment (`clock_adjustment`). The loop guard's `cycle` note (turn 99, 8:03 PM), the `interface_dwell` stall briefing (turn 127, 8:06 PM) and the `milestone_drought` briefing (turn 139) were ignored.
- `runs/2026-10-20T20-26-22_qwen36-gpu1_97a0` (still being written when read), from turn 116 (8:35 PM New York): `navigate_to_target` warp (14,8) on LITTLEROOT TOWN into PROF. BIRCH'S HOUSE, then warp (2,8) back out, turns 116-122; then from turn 120 a 3-turn rotation through 132: in, the same call again (staying in the house), out. Map-cycle and cycle loop-guard notes fired and were ignored.

Why the existing collapse never acted (from `fixed-point-breaker.ts` and `same-plan.ts` `planState`):

1. Its run needs every turn to leave the same state; these repeat with period 2 or 3.
2. Its group key includes thinking and text; in ef9f the six bounce turns 131-136 have six different thinking texts, in 97a0 turns 116/118/120/122 have three and 117/119/121 two.
3. `planState` is null for any screen other than the overworld or a ready battle, so ef9f's `clock` screen never qualifies.
4. `planState` includes the interface's `value`; each ef9f cycle moved the clock 2 minutes (10:58, 11:00, 11:02 ...).

Approval: The operator, 2026-10-21 00:08 UTC (8:08 PM ET): "lets do those fixes and put them in the bundle" (relayed by the coordinator), for the two-state ping-pong. Scope widened by the coordinator on the 97a0 evidence (extending the operator's approval): cycles of period 2-4 over (tool call, resulting state) pairs; thinking need not match when calls and states repeat exactly; fire once the cycle has repeated as many times as today's rule needs; keep the ef9f case; rename if the name no longer fits.

## Architecture

- Owner: `FixedPointBreaker` (`packages/agent/src/fixed-point-breaker.ts`), constructed by `fixedPointBreaker()` only while duplicate-turn-collapse-v1 or fixed-point-breaker-v1 is on. The switch is read once in its constructor from the FeatureSet.
- Turn item: the turn's tool calls (names and arguments, JSON) plus the `cycleState` each result left, in call order. Since fix batch 4, `cycleState` is a SHA-256 of `cycleFields(state)`: the whole recorded state event minus `CYCLE_STATE_EXCLUDED`, an exported, documented list of fields that change on their own — the event envelope and counters (`v`, `run`, `type`, `seq`, `turn`, `t`), `raw_ram` (archive reference: frame, path, sequence, hash), `settle` (frames the observation waited), `play_time_s`, `active_ui.value` on the two clock phases only (the entry names those phases; ef9f moved the clock two minutes each cycle), and `resources.berry_trees[].minutes_until_next_stage`. Evidence: between repeats of ef9f's bounce (131/133/135 and 132/134/136) and 97a0's walk (116/118/120, 117/119/121) only these fields differ. Everything else is in, including the whole party and battle records (PP, experience, moves), inventory, berry trees, script registers, objects and maps. Null where the readout cannot qualify the state: before the game starts, an interface that is not ready, any key ending in `diagnostic` with a value or in `diagnostics` with entries anywhere in the state (since round 5: `nickname_diagnostic`, `message_diagnostic`, `daycare_*_diagnostic`, `*_pokemon_diagnostics` and the like), the field without map, position or facing, a battle without its interface, or another screen without a ready interface. A reply with no tool call or a turn whose results never all arrived is null too. Null items never join a cycle. A test walks every key path of three real recorded states (ef9f turn 133, 97a0 turns 120 and 121) and of 97a0 turn 121 with a naming keyboard open (a non-clock interface with a value), and fails if a path is neither fingerprinted nor on the list (phase-limited entries apply only in their phases); a second sweep gives every recorded key ending in `diagnostic(s)` a failure and requires a null state.
- `cycleRuns(items)`: maximal runs where every item equals the one `period` items before it, period 2, 3 or 4, whose first block is primitive (A,B,A,B counts as period 2; all-identical blocks are left to the identical-turn rule), with at least `CYCLE_COPIES` = 3 copies (3 × period turns). Documented equivalent of today's rule: identical turns need 3 copies of a 1-turn block; a cycle needs 3 copies of its block.
- Stage 1 (collapse): each run keeps its newest copy (the last `period` turns, less any identical turns the identical-turn pass already left out); earlier turns join the drop set after today's identical-turn pass. Overlapping runs of different periods can leave out part of an earlier run's newest copy (those turns are earlier copies of the later run). Recorded as `loop_breaker` stage 1, trigger `short_cycle`: `collapsed` counts every group the cycle pass left out of that request across every cycle in it (as today's `collapsed` counts all runs); `repeats` and `period` (required on `short_cycle` records since fix batch 4) describe the longest cycle. Activity History says "… left out of the request across every cycle in it (longest: a cycle of P turns … repeated over N turns)".
- Stage 2 (note, fixed-point-breaker-v1 only): from recorded events the breaker keeps the latest 4 turn items and, for each period, the length of the run ending at the newest turn (as `cycleRuns` counts it, so a long cycle is counted whole); a turn whose results never all arrived counts as a break (as stage 1's null item does). When the newest turns are in a run longer than 3 copies (3 × period + 1 turns) the request ends with `cycleNote`: "SUPERVISOR: Make one tool call based on the game state and what you observed. Your last N turns repeated the same P turns of <tools> calls, and each time round the game came back to the same sequence of screens, positions and highlighted choices." (Round 1 replaced "the game state came back to the same P states", false when the clock's time moved; round 2 replaced "the same P screens, positions and highlighted choices", a count that is wrong for multi-call turns and the one-screen clock cycle.) Recorded as stage 2, `short_cycle`, with `period`. Errored or aborted replies are skipped, as today's streak skips them.
- Stage 3 (auto-talk) reads `fixedPoint()`, unchanged: it acts only on the free field and its message says the state "stayed the same", which would be false for a cycle.
- fresh-retry-v1 concerns replies with no tool call; cycle turns all call a tool, so it is unaffected.
- Viewer: Activity History label for `short_cycle` (with the period, and "across every cycle in it" for stage 1); loop_breaker never reaches the timeline. Schema regenerated (`short_cycle`, `period`).

### Decision: thinking and text need not match

From the evidence: ef9f's thinking differs every bounce turn (six texts for 131-136); 97a0's walk has three texts over four "in" turns and two over three "out" turns. With identical thinking required, neither run would ever fire. The coordinator also directed that identical thinking not be required when calls and states repeat exactly. The calls (names and arguments) and the resulting states must repeat exactly.

### Decision: keep the newest copy of the cycle, not only the newest turn

The identical-turn rule keeps one copy of the repeated unit (one turn). For a cycle the unit is `period` turns; keeping only the newest turn would hide the cycle's other calls, so the request keeps the newest copy (2-4 turns). For ef9f's single call this keeps the confirmation turn and the adjustment turn.

### Decision: the cycle state is the whole recorded state minus a documented list

Rounds 1-4 each found a field the hand-picked fingerprint missed (interface values, inventory, berry trees, diagnostics, PP and experience). Fix batch 4 (coordinator's direction) inverts it: everything recorded counts unless it is on `CYCLE_STATE_EXCLUDED` with a reason, and a key-walk test keeps the list honest. Without the clock-time exclusion and qualifying interface screens, ef9f could never fire (null fingerprint on the clock screen; the clock value moves each cycle). With the whole state, 97a0's 3-turn rotation of calls from turn 120 (collapsed at turn 129 under the hand-picked fingerprint) no longer counts: the house's objects differ between its turns 120 and 123 (a NINJA_BOY at (9,5) at turn 120 is gone at 123; `world_context.objects`, `interaction_targets`, `interaction_object_slots`, `local_map`, `map_grid`, `navigation_grid` differ). That is a real change in the visible game, so it is not excluded; reported to the coordinator. ef9f still first fires at the turn 137 request and 97a0 at the turn 122 request.

## Invariants

- INV-1 OFF is byte-identical: no cycle state, history, collapse, note or event. Tests: OFF rigs equal the input messages; OFF equals today's output for identical turns; ef9f and 97a0 replays OFF record nothing.
- INV-2 Fires at 3 copies (2-turn cycles at 6 turns, 3-turn at 9, 4-turn at 12); the note one turn later.
- INV-3 A different call, any change in the recorded state outside `CYCLE_STATE_EXCLUDED`, a state with a diagnostic, a null state or a reply with no tool call breaks a cycle; a cycle is counted by its shortest period; identical turns stay today's rule.
- INV-4 Timeline closed: no new mark, lane, label or color.
