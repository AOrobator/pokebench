## Problem and frozen scope

Distinct visible mechanics collapse into ordinary floor/walls or ambiguous symbols. Rotating gates have a separate edge-collision owner. Typed state, map text, adjacent descriptions and interaction labels must describe the same coherent current snapshot. This is one integrated observation milestone with three parallel decoder lanes; none is independently activated or landed before the common contract and combined reviews pass.

Canonical versioned map-observation schema: current map ID, viewport origin/size, sparse typed elements, readiness/unknown notes, and current layout context where validated. Elements retain kind, coordinates, current state, direction, visible color, group, orientation and optional edge endpoints. Raw collision/elevation remains authoritative and unchanged. One renderer derives unique tokens, legend, coordinate facts and adjacent/interaction labels from these elements. Player/object/warp occupants retain separate identity and never erase the underlying element. Rotating-gate arms describe edges between tiles, never fabricated solid cells.

Visible tile providers are map/tileset qualified; no remembered or predicted switch effects. Only currently supplied tiles are annotated. Native rotating-gate bytes require exact map/config/ROM identity and animation readiness; unsupported data reports unavailable. Old recordings remain compatible; new metadata declares the feature. Explicit OFF preserves prior readout/state bytes. Fresh control and bundle default ON by direct authorization; active and queued frozen runs remain untouched.

Coverage: generic terrain and special transitions; Mauville adaptation; New Mauville; Trick House2/3/6/7/8; Mossdeep; Fortree; observable Petalburg/ship doors; ice/cracked floors/rails/currents/bridges/water distinctions; narrow generated-map dimension correctness where source proves it. Dynamic layout context is read from current validated ownership. Optional encounter/palette/inscription mechanics lacking a validated current owner remain explicit audit entries, not guessed game facts.

Non-goals: planner route changes, warp execution changes, movement automation, puzzle solutions, hidden item/actor revelation, darkness-policy changes, new timeline marks, trainer-card redesign, trial launches, hotpatching or active-run restarts. Prior audit's planner contradictions remain separately tracked; this request narrows implementation to observation.
