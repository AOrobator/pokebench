## Problem Statement

Once a run has the bike (Mauville, BICYCLE_RECEIVED), the harness still walks or runs everywhere. On a cycling-allowed map the Mach Bike covers a tile in 4 frames at top speed and the Acro Bike in 6, against 8 running and 16 walking (measured below). Riding needs three things the harness does not do today:

1. The bike must be registered to SELECT. A new save has `SaveBlock1.registeredItem` (SB1+0x496) = 0. In all six post-bike checkpoints of run `2026-10-25T10-50-57_gpt-6-astra_429f` the MACH BIKE (259) is in KEY ITEMS and nothing is registered.
2. Navigation must work on a bike. Today strides stop with "field input unavailable" whenever `running.reason == "not_on_foot"` (`env/pokebench_env/strides.py:167`). The per-press `navigate_to` check assumes a fixed span; an Acro Bike 10-frame press crosses 2 tiles, which ends navigation with "unexpected movement".
3. Something has to get on and off at the right times.

## Architecture

All per-frame timing is owned on the game server, like strides and the intercept. The agent decides when; the server presses and verifies.

### `bike-navigation-v1` (needs `safe-navigation-strides-v1`)
- Env `strides.py`: `StrideRequest.bike: bool = False` (absent = today). With `bike` and the avatar riding (flags & 0x06, not surfing/underwater), `not_on_foot` is accepted. The bike stride holds the direction while `remaining > coast` (Mach: `bikeSpeed`; Acro: 0) and releases otherwise, so a released Mach Bike coasts onto the last tile and never past it. Progress is the index of the current destination tile in the corridor; any tile outside the corridor stops it. Every step a hold would start is checked with the same `_safe_next` corridor check; the tiles a released Mach Bike coasts over were checked at planning and just before the press, not again mid-coast. Tiles where the game disallows biking are never in a corridor (plain floor and tall grass only). Bike corridors may run 16 tiles. B is never held. `automatic_running` must be false with `bike`.
- Agent `stride.ts`/`navigation.ts`: when riding, `planStride` adds `bike: true` and the stride runs with automatic running off. A non-stride press while riding accepts the actual end tile when every crossed tile is the next collinear prefix of the route (the `runningPrefix` rule), instead of a fixed span.
- OFF: requests, receipts and planning are byte-identical.

### `bike-register-v1`
- Env `bike.py`: `read_bike(read)` → `{owned: [259|272…], registered, riding: "MACH BIKE"|"ACRO BIKE"|null, allow_cycling}` from SB1 key items (+0x5D8, 30 slots), SB1+0x496, gPlayerAvatar flags/+0xB and gMapHeader 0x1A bit 0. In the state JSON as `bike` only when a bike server switch is on.
- Env `POST /pokebench/bike/register {id, item}`: a frame-owned state machine that presses one button at a time and waits for the native menu readout to change (no sleeps): START, START-menu cursor to BAG, A, pocket to KEY ITEMS, list cursor to the item, A, context cursor to REGISTER, A, then B until the field is back. Done only when SB1+0x496 reads the item back and the field is free. An unanswered press is pressed again after 30 frames (3 tries). An unexpected phase or a press still unanswered stops with a reason after closing the START menu or bag with B; frame budget, cancel and queue interruption stop at once, which can leave a menu open for the next step to report. Frame budget 1200.
- Agent: before navigation moves, if a bike is owned, none is registered, and the field is free, run it once per distinct `registered` value (so it runs again only if the registration changes).
- Readout line: `Bike: MACH BIKE registered to SELECT`.

### `bike-auto-mount-v1` (needs both)
- Env `POST /pokebench/bike/toggle {id, ride: bool}`: requires a free field and the opposite riding state; presses SELECT once; done when the avatar flags show the wanted state and field control is back. For getting on it also requires `allowCycling`, on foot, not surfing, and the player's tile not one the game refuses. Frame budget 120. If the game prints a refusal instead, it presses B once to close it and reports `refused`.
- Agent, at the start of each navigate_to step: get on when cycling is allowed, the player is on foot, a bike is registered, riding the planned route takes fewer frames than running it (see M4) and its next tile is not one the bike cannot enter. Get off (SELECT, confirmed by flags) before a step onto water or a tile where the game disallows biking. Warps: rely on the game's own dismount and verify from the next state.
- Readout: the same line gains `; riding it` while riding.
